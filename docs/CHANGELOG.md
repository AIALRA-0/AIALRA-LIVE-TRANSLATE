# 变更记录

## 1 2026-08-29 长时恢复与线上安全

### 1.1 浏览器与私网恢复

- 浏览器重连后最多保持 8 个音频帧在途，ACK 到达后再发送下一帧，避免长时断线后一次性淹没 WebSocket
- 浏览器进度同时检查本地采集序号和服务器确认序号，ACK 连续停滞会主动失败并保留证据
- SSH 转发增加 keepalive、失败退出和 1 秒监督重连，替代静默失效的单次转发进程
- 真实故障矩阵覆盖 Core 重启、GPU Agent 重启、Worker Gateway 中断、ReadWeave 离线、乱序上传、精确重传和第二设备接管

### 1.2 本机模型与启动

- base CPU 长测确认恢复稳定后，`small + CPU int8` 的 8 秒直接基准 p95 为 2.211 秒
- small CPU 与 3B CUDA 独立 30 分钟门禁完成 1183 个音频块和 394 个模型任务，ASR 端到端 p95 为 2.739 秒，成为当前默认组合
- CPU ASR 使用 12 个线程，模型 Worker 使用 Windows `AboveNormal` 调度优先级
- Agent 启动前依次预热 ASR、Ollama 和 ASR，确认模型真实可用后才领取生产任务
- 安装器验证系统 Ollama 中存在目标模型，并持久保存已验证的回环地址和模型名
- 健康检查要求配置模型至少 90% 驻留 GPU，不能仅凭 Ollama 进程存在声称 CUDA 可用

### 1.3 ReadWeave 与公开入口

- ReadWeave 页面接入统一 Authentik 登录，匿名访问返回登录跳转
- 公网 `/etapi/` 固定返回 `404`，Core 继续通过 VPS 私有回环或容器网络访问 ETAPI
- 新增脱敏 ReadWeave Nginx 模板，不在仓库保存真实域名、地址或证书路径

### 1.4 验证工具

- 长测数据库报告增加最近 20 个任务的 Provider 和端到端 p95，以及当前任务状态计数
- CPU ASR 基准支持显式模型选择，只输出耗时和非空计数，不输出转写内容
- 生产依赖审计、Rust 29 项测试、Web 13 项测试、Python 16 项测试、Android 完整构建和 DingTalk 小程序测试通过

### 1.5 README 与公开发布

- README 首屏统一居中，正文保持左对齐，并替换为真实模型链路生成的黑白页面截图
- 截图隐藏运行标识和时间，移除图片元数据，并通过亮色、暗色和窄屏浏览器检查
- 公开候选分别通过精确工作树和完整公开历史安全门禁，两次结果均为 `pass / allow`
- 公开 `main` 使用普通快进提交更新，发布后读回确认提交、Git 树、可见性和 README 均与门禁候选一致

## 2 2026-08-28 项目同步、录音租约与 ReadWeave

### 1.1 项目和多设备

- 新增 Authentik UID 所有的项目、项目会话和统一更新游标
- 新增项目列表、详情、修改、会话和 SSE 恢复接口
- 同一用户的多台设备共享会话状态和完整时间线，不同用户严格隔离
- Nginx 删除客户端身份头，只把受信代理返回的稳定 UID 写给 Core

### 1.2 单录音设备租约

- 新增 45 秒项目录音租约、10 秒续期、generation 接管和明确的冲突响应
- 允许过期但尚未被其他设备接管的原录音设备使用同一密钥续回，以补传长时间断网期间的缓存
- 音频 WebSocket 使用子协议传递租约密钥，旧租约和旧 generation 不能继续上传
- 租约续期响应只返回公开状态，不向浏览器返回服务端保存的令牌摘要
- Web 和 Android 都在录音前取得租约，停止时先排空已接受音频再释放租约
- 浏览器刷新和短时断网后从 IndexedDB 恢复未确认帧及后续序号

### 1.3 持久音频装配

- 新增音频块、装配游标和窗口组成范围的持久记录
- ACK 改为只在对象存储和 SQLite 事务完成后返回
- Core 重启后扫描未装配块，停止时从数据库封存尾部
- 修复重复课程音频被内容哈希误去重的问题，ASR 幂等键加入会话、来源和采集时间
- 新增首帧缺失、乱序补传、相同重传和冲突重传测试

### 1.4 ReadWeave

- 新增持久连接器任务和本地对象到远端 note ID 的稳定映射
- 自动建立课程概览、实时转写与翻译、生僻词与补充解释、课件证据索引和用户笔记
- 写入前创建 revision 并重新读取远端，只替换 AIALRA 管理标记内的内容
- 人工区域和用户笔记永不覆盖，标记缺失时建立恢复笔记并显示冲突
- 后续成功同步会清除当前冲突状态，历史冲突仍保留在项目更新记录

### 1.5 GPU 调度

- ASR、翻译和讲解拆分为独立领取通道
- 14B 在 30 分钟数据库门禁中因长讲解阻塞翻译而失败，该结果保留但不计入通过
- 7B 真实并发预检通过后成为默认翻译和讲解模型
- 5 分钟线上预检完成 298／298 ACK、60 条字幕、60 条译文和 12 张讲解卡，端到端 p95 均通过冻结门禁
- Ollama 双并发预检完成 297／297 ACK，Worker、ASR、翻译和讲解端到端 p95 均通过
- 30 分钟网络音频完成 1785／1785 ACK、357 条字幕、357 条译文和 71 张讲解卡，三次断网恢复、重复 0、OOM 0

### 1.6 页面与客户端

- 单页工作台加入项目选择、录音设备状态、同步观察和 ReadWeave 状态及预览
- 页面保持黑、白和中性灰，红色只用于录音、停止、拒绝和错误
- Android 缓存按租约 generation 隔离，停止动作等待未确认帧全部 ACK 后再释放服务器租约
- 生产构建仍不注册测试音源、演示路由或默认 mock

### 1.7 依赖安全

- 更新兼容范围内的 Rust 锁定依赖，生产前端审计和 RustSec 审计均无已知漏洞
- Core 限制 glibc 分配 arena 数并降低空闲页回收阈值，避免长时间 ReadWeave 全量投影把临时内存长期保留在多个工作线程

## 3 2026-08-27 真实 GPU 混合链路

### 1.1 持久任务与恢复

- 新增 SQLite `model_jobs` 与 `worker_nodes`，支持优先级、租约、续租、重试、幂等键和重启恢复
- 音频窗口落盘后只创建 ASR 任务，ASR 完成后创建翻译任务，讲解与材料任务不阻塞实时字幕
- 停止录音时封存尾部音频，会话使用 `processing` 区分录音停止与模型完成
- GPU 离线时继续 ACK 和持久排队，不生成 mock、identity 或 deterministic 结果

### 1.2 私有 GPU Agent

- 新增私有 Worker Gateway、心跳、长轮询、任务下载、完成和失败接口
- 新增 Windows RTX GPU Agent，ASR 与 LLM 使用独立执行通道
- Worker 明文令牌使用 DPAPI 保存，服务器只保留 SHA-256 摘要
- Agent 支持退避重连、60 秒租约、20 秒续租和登录自启动
- VPS CPU Worker 与默认 Ollama 服务退出当前生产主路径

### 1.3 浏览器与视觉

- 麦克风采集改为 AudioWorklet，未确认音频写入 IndexedDB 并在恢复后重发
- 新增浏览器标签页与系统共享音频入口，并保留来源 ID
- 删除生产默认演示开关与 `/demo` 路由
- 页面改为黑白层级，红色只用于录音、停止、权限拒绝和错误
- GPU 状态、队列深度、处理位置和真实 Provider 进入同一课程页面

### 1.4 验证

- 本机真实 GPU：21／21 ACK，4 字幕，4 译文，1 材料页，1 讲解卡，14.201 秒
- 私有远程 GPU：21／21 ACK，4 字幕，4 译文，1 材料页，1 讲解卡，35.015 秒
- GPU 离线恢复：离线时 0 假字幕与 5 个排队任务，恢复后重复字幕为 0
- Core 重启恢复：任务与 `processing` 状态保留，恢复后重复字幕为 0
- 浏览器桌面、暗色与 390 px 窄屏通过，控制台错误与警告为 0
