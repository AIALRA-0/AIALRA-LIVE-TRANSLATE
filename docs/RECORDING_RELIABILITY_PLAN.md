# 录音、翻译与阅读体验修复批次

起点：v33，运行提交 `cb8564a`；本批针对用户反馈的十项实际问题，按下列顺序实施和记录证据

| 顺序 | 改动与原因 | 验证产出 |
|---|---|---|
| 1 | 历史租约事件只触发当前状态查询；取消、卸载、测试结束均释放本页音频资源；设备错误分开解释 | 重放旧事件、新课程、权限延迟、取消和重复开始的浏览器回归 |
| 2 | 常亮锁绑定实际录音生命周期；系统释放后重新申请；结束和卸载释放迟到的锁 | 请求竞争、系统释放、结束后无锁的测试 |
| 3 | 课程完成、处理、失败、归档和许可缺失有独立原因与操作；恢复不改写历史 | 状态接口、第二设备冲突、原课程恢复与新课程入口 |
| 4 | 集成现成 RNNoise WASM；保留浏览器降噪和原声选项；共享视频音频保持原声 | 音频线程运行、失败回退、帧完整性及合成噪声比较 |

| 6 | “新建项目”按钮仅建项目；目录操作保留在右键；五个模块分别显示内容、空态和动作 | 桌面／390px、亮暗主题、笔记自动保存、术语查询与录音定位回放 |
| 7 | 工程测试、脱敏、main 普通推送、远端构建、健康门、合成生产验收 | 四份状态文档与运行版本、未完成证据明确对应 |

## 已确认的起因

- Project SSE 会重放历史租约，前端收到旧的其他设备租约后直接撤销本机录音，不能据此判定当前持有者
- `NotReadableError` 被直接表述为“其他应用占用”，超出了浏览器实际给出的信息
- HY-MT 使用通用聊天 system prompt 和自定义 Source/Target/Context 包装，与官方专用模板不一致
- HTTP 超时不保证后台 Python 推理线程停止，Agent 释放调度锁后可能发起下一次请求，造成实际推理重叠
- 最新现场曾出现显存接近 16 GB、GPU 100%、翻译积压；新增 ASR 失败需结合修复后的真实请求复核，不能把 Core healthy 当作模型健康

## 质量判断

沿用用户决定，以真实体验验收质量；同时记录源文本完整性、译文事实／数字／否定关系、首结果与稳定结果延迟、队列等待、失败和重试。参考 SimulEval 的质量与延迟分开计量方式，不能用一次短合成冒烟宣称达到所有商业产品的效果

YouTube 链接的网页读取未提供可用音轨或字幕；不将链接读取失败写成已经测试该视频。真实视频复测使用浏览器“共享标签页音频”入口，避免扬声器再次经麦克风和回声消除处理

Paneltone 本批不停止、不修改；显存外部占用仍需真实资源观测，不能宣称单一产品能保证其他进程永不争抢 GPU
