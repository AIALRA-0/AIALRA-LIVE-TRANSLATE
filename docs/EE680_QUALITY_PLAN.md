## 1. 这次要交付什么

你需要的是能连续听课的产品：先把老师的话听完整，再联系上下文翻译；一段主题讲完后，用完整、易懂的段落解释，并逐项说明术语；换人说话时能看出是谁。我们负责选技术、准备测试、部署和保留证据，不能把这些工作转交给用户。

不把“所有请求成功”当成“内容正确”，也不承诺尚未证明的绝对准确。旧版保留在线，新实现用同一批音频和事实检查表证明改善后才替换。

源码还确认：静音以 450 ms 平均幅度判断，阈值会把弱声算作静音；四个识别片段即可强制组成翻译段落；当前专用翻译模型不读取自由历史上下文；讲解限制为一至三句、概述最多 300 字、总输出预算 640 token。课程总结另有 420 token 默认输出预算和 3,072 token 上下文预算。这些是需要修正的实现约束，不等于已证明每个错字的原因。

用户感受到的 5%–20% 错词先按体验反馈记录。没有独立参考稿前，不将其写成实测 WER。

## 3. 技术选择及取舍

### 先修输入和断句，不立即更换识别模型

保留 Qwen3-ASR-1.7B 作为第一轮候选，先排除切片损失。把传输块、识别窗口、语义句子、主题组分开：一秒传输块负责可靠保存，不决定句号；识别保留未说完的尾部；完整句子负责翻译；相似内容组成主题组。

先用保守的短帧能量判定修复弱声误切；这只是边界保护，不冒称为神经网络 VAD。后续在固定样本上比较成熟 VAD 与现有方式。保留原音对照、处理开关和处理版本；EQ、降噪只在同输入对照确实改善后启用，不给所有麦克风套统一增益或 EQ。

[Qwen 官方](https://github.com/QwenLM/Qwen3-ASR)提供流式入口，但目前官方流式实现依赖 vLLM，且不返回时间戳。不能在当前 Windows GPU 环境中把加一个参数说成原生流式已经可用，也不为此启动被禁止的 WSL。可先实现暂定文本与稳定文本分离，并验证连续窗口的一致前缀；参考 [SimulStreaming](https://github.com/ufal/SimulStreaming) 的稳定提交策略，保留来源和 MIT 许可，不整套照搬不适用的模型栈。

### 翻译比较三种路径，不凭模型大小下结论

同一固定输入比较：当前独立片段翻译；官方有边界的上下文翻译；现有本地指令模型的受约束翻译。对比代词、承接、数字、否定、条件和术语，不只看语言流畅。

[HY-MT 官方模型卡](https://huggingface.co/tencent/HY-MT1.5-1.8B)有专门的上下文模板。历史上自由拼接上下文曾造成上一段数字混入当前译文，因此不能简单恢复拼接。请求必须区分“只供参考的上下文”和“这次唯一要翻译的原文”，响应绑定原段 ID 与修订号；上下文按课程隔离，只选源文，不把错误译文递归当成事实。若模型返回上下文复述或提示词标签，拒绝作为正式译文，最多有限重试并显示清楚的待处理状态。

第一版不同时常驻多个大模型抢占 16 GB 显存。ASR、翻译优先；讲解和总结排在后台。测量模型换入换出时间，不能只优化推理忽略排队。

### 讲解按主题写完整，不按字数假装完整

主题判断输入包含相邻完整段落、时间间隔和新旧主题的语义变化；输出必须是已有段落之间的边界，不创造或跳过段落。同一主题连续追加，出现真实转折才关闭；时长、输入容量只作为兜底。达到容量边界但主题未变时标注“同主题续”，不能伪造主题结束。

先用本地轻量语义候选与带来源段落的模型判断做离线对比。不能用固定 16 句、关键词不重合或人工写几个主题词，就宣称实现了语义分组。模型判断不能阻塞收音和译文；没有确定边界时保留待成组内容，停止时封存尾组。

每组输出：

1. 简洁主题标题。
2. 一段或多段完整解释，按“讲的是什么—为什么—怎么起作用—条件、例外和例子”的实际内容顺序展开；不强行补齐原文没有的项目。
3. 术语清单，每项一行。给出术语、确知的英文全称或缩写、它是什么、在本段有什么作用。解释长度随概念需要，不强制一句极短话；不知道缩写全称时不编造。
4. 每项解释与术语保留真实来源段落。补充的通用背景单独标识，不冒充老师原话；不生成听写猜测、复习问题。

不再硬压 300 字或限制 12 个词。输出采用有预算的分组生成和覆盖检查：先提取原文中的事实、条件、数字与术语，再逐项检查解释是否覆盖。输入超过预算时分批归纳并合并，不截掉课程中间内容。若生成被长度限制截断，不将一个勉强可解析的 JSON 当成完成。

课程最终总结使用已经验证过的主题组，再回查遗漏的原始段落。每次生成附带完成状态和缺失项；格式验证只证明结构合法，不能证明内容完整。

### 说话人区分先走 CPU，编号不冒充身份

目标是同一课程中的说话人分离，不是识别现实身份。默认“说话人 1、2”，用户可以改显示名；不自动猜名字、性别或其他属性，不跨课程匹配声纹。

优先验证 [sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html) 的分段与说话人向量方案，复用成熟推理接口，限制 CPU 线程。候选模型本身单独核实许可、下载和运行条件。[pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)可作质量对照，不能绕过其模型访问条件。若需大型 GPU diarization 模型，先证明其资源收益，不默认挤占 ASR 显存。

编号按首次可靠出现分配，缓存按课程和录音来源隔离并可恢复。短促回应、远处弱声、重叠说话没有足够证据时显示“说话人待确认／多人重叠”，不为了每段都有编号强行归类。声纹向量仅保存在受控本地数据中，随课程删除，不写日志和 Git。

## 5. 怎么判定真的改善

数据安全是硬条件：已经确认的音频缺块、重复或顺序错误为 0；模型不阻塞 ACK、续租或停止；只追加修订，不覆盖历史；不同项目不能串话、串译文或串说话人。

质量测试由系统准备：先固定样本，再看候选结果。长课覆盖开头、中间、结尾、术语密集、弱声、句中停顿和换人场景。独立参考稿必须逐段听音复核；字幕和另一个 ASR 都只能辅助，不能直接当真值。两条模型轨比较必须用完全相同的音频、处理版本和语言设置。

以下是本轮工程验收目标，不是已经取得的结果，也不重新启用用户已放宽的“所有困难样本 99%”死门：

- 识别：相同测试集漏词和替换明显少于 v35；建议目标为总体 WER 相对下降至少 30%，关键数字、否定和术语单独逐条核验。改善是否达到使用要求仍以固定样本和真实课程可读性共同判断。
- 翻译：固定测试集中关键数字、否定、条件错误为 0，提示词残留为 0；指代与段落承接盲评优于 v35；空结果不能伪装为完成。
- 讲解：检查表中所有有证据的关键事实、条件和术语均被覆盖；新增错误事实为 0；来源缺失项必须显式失败，不用“更长”代替完整。
- 分组：同主题连续内容不因凑够句数频繁生成；明显主题变化后及时建立新组；每个原段恰好进入一个主题主组，继续主题可有关联但不重复生成全文。
- 说话人：清晰非重叠测试首先争取时间加权误分不超过 5%；重叠和低证据另报，不并入平均分掩盖。会话恢复不随意换号，额外处理实时因子不超过 0.1，ASR p95 不因该功能上升超过 10%。未达到时保持实验关闭，不输出假确定编号。
- 延迟：先报告音频尾部到稳定原文、稳定原文到译文、排队和推理各自 p50/p95；识别 p95 首先低于本次 15.506 秒，目标 5 秒以内。不能把等待完整句子的时间从总延迟中扣掉。预览文本与最终结果延迟分别标明。
- 停止和中断：正常停止先保存尾音再确认；没有有效租约后在一次状态刷新内（最多 10 秒）不再显示正在收音；网络中断不假报“全部保存”；重复停止不重复生成任务。
- 长课：至少覆盖这次约 37 分钟同等负载及多项目场景，确认队列能排空、内存不持续增长、Core 无新增重启。不是另立 6/24 小时发布门。

## 6. 发布、恢复和交付

直接在 main 上保留本任务改动，不创建分支，不修改其他项目。每个有意义修改都有对应测试。只做关键脱敏检查；真实课程、音频、文本和模型输出留在仓库外私有证据目录。

正式切换前核实无有效租约、队列为空、GPU 可用、磁盘和旧版恢复资源齐全。仅远端 Docker 构建，不启动本地 Docker/WSL，不删除持久数据。健康、身份、ACK、停止和 SHA 任一失败立即保持或恢复旧版。

本轮 Core、Agent、Model Worker 有联动契约，不能只发布网页与 Core，就把仍运行旧代码的 Worker 当作已经更新

- 候选资格通过后记录旧 Core 发布、当前 Agent／Worker 启动方式和非秘密模型配置，保留现有凭据，不重新安装、不改 Gateway
- 确认没有活动租约和任务后，通过本项目监督器暂停领取新任务，构建失败仍保留原 Core 与原 Worker
- 远端 Core、同 SHA 的 Agent／Worker 和已验证模型配置一起切换，只有实际预热与心跳证明目标模型就绪后才恢复领取任务
- 单 LLM 常驻候选只在 ASR 为 Qwen CUDA，且翻译、主题、讲解、总结配置相同时启用，不能仅凭环境变量打开未测组合
- 说话人依赖与模型路径单独确认，模型不放入 Git，不在用户开始录音时临时下载；许可证据与恢复路径留在私有部署记录
- 回滚必须同时恢复旧 Core 和旧 Worker 配置，恢复后核实真实 Provider、有效租约、队列和版本，不能只恢复 symlink 就宣布成功

未经用户明确同意，不把术语校核实验变成新的云端出口；即使同意，也必须先由服务端限制发送字段和目的地，不发送录音、课程原文或材料

用户 Router 已完成一次仅限通用公开概念的受限咨询，实际使用 GPT-5.6 Sol，凭据保存在仓库外当前用户保护的秘密存储中，未传课程、音频或材料；课程文字对照需另获明确许可，不能从架构咨询权限推导出生产云端出口。

最终交付同时提供：实际上线版本、工程测试结果、同输入质量对照、失败与未完成项、真实浏览器验证、恢复方法。自动化通过和用户认可分开记录；声纹分离、语义分组或质量对比没有实测通过时，不能写“全部完成”。
