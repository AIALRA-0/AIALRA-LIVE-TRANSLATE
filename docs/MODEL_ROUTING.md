# 模型分层与授权边界

## 2026-09-22 当前候选路由（以下旧章节仅作历史记录）

课程讲解、整课总结和问答在服务端允许且项目显式授权 `text` 后，由 Windows GPU Agent 直接调用夸父社 DS；主、备密钥分别来自进程环境 `AIALRA_KUAFUSHE_DS_PRIMARY_KEY`、`AIALRA_KUAFUSHE_DS_BACKUP_KEY`，不写入 Git。默认两条均为 `https://api.kuafushe.cc/v1/responses` 的 `deepseek-v4.1-flash`，凭据或输出合同失效时改试另一条。两条共享提供方，只构成单凭据级互备，不能承诺提供方整体宕机时仍可用。运行请求不经过 ReadWeave。

Core 的生产 Compose 默认 `AIALRA_LOCAL_ONLY=true`、`AIALRA_CLOUD_TEXT_ALLOWED=false`，且项目默认无云端授权；两级条件未同时满足时继续本地讲解，音频与图片不因文本授权外发。ASR、HY-MT 翻译、话题判定、材料解析和原生远程 GPU Broker 链路不切换。音频接收、持久确认及停止始终优先于模型任务。材料只解析入库，讲解时按需选取有限相关页；话题检查窗口按稳定段落长度自适应，语义边界仍需真实课程复核。最新证据与未关闭问题见 `VALIDATION_REPORT.md`、`KNOWN_ISSUES.md`。

以下 2026-09-12 原方案中的固定模型、固定八段、独立凭据要求与云端关闭结论均已被本节替代，不得当作当前配置。

状态日期：2026-09-12

## 1 当前决定

专用 Qwen3-ASR 负责实时识别，专用 HY-MT 负责稳定段落翻译；7B 只负责内容组讲解，14B 只负责停止后的最终总结，Qwen3-VL 8B 负责本地图片理解

这不是按参数量猜测，而是按 RTX 4080 上的真实延迟、显存、结构化结果和长时稳定性分工

云端增强默认关闭，没有独立应用凭据或逐项授权时，页面不得创建云端任务，也不得把本地失败改成云端占位结果

## 2 本地模型分层

| 任务 | 默认模型 | 当前证据 | 结论 |
|---|---|---|---|
| 实时 ASR | `Qwen/Qwen3-ASR-1.7B` CUDA | v31、v32 生产合成链路已产生稳定字幕；用户反馈识别质量已明显改善 | 保持最高优先级；静音窗口先在 Worker 侧拦截，禁止 CPU 静默回退 |
| 实时翻译 | `tencent/HY-MT1.5-1.8B` CUDA | v31、v32 生产合成链路已产生稳定译文；真实多语言准确性仍由用户体验验收 | 按稳定段落翻译，保留有限上文只解决术语和指代；输出必须通过目标语言和格式契约 |
| 内容组讲解 | `qwen2.5:7b-instruct` CUDA | 新内容达到 8 个稳定段落且约 1,600 字符后检查话题；20 段或约 4,000 字节时封住本次检查窗口，停录后补齐尾段 | 话题模型决定边界，讲解只对已确认的内容组生成总结和术语解释；录音任务优先处理 |
| 最终总结 | `qwen2.5:14b-instruct` CUDA | 历史 90 分钟验证中单次约 17 秒完成；当前专用模型组合仍需真实课程复核 | 停止录音且实时任务排空后运行一次，超过 120 秒进入可见失败和重试 |
| 图片理解 | `qwen3-vl:8b-instruct` | 冷启动 48.743 秒，热运行 12.906 秒 | 只在实时队列空闲时运行 |

旧提示词和过大的无结构输入曾让 14B 总结超过 180 秒；当前实现改为证据约束输入、有限重试和专用总结契约，最新 90 分钟正式轮次在 17.049 秒完成，但 6 小时和 24 小时仍需独立验证

## 3 为什么不再按声学碎片逐条翻译

ASR 的短窗口用于降低识别延迟，不等于可直接阅读的语言段落

V17 保留声学片段作为追加式证据，但先按终止标点、长度和片段数量整理成连贯段落，再创建一项 7B 翻译任务；网页和 ReadWeave 默认只呈现段落，内部片段仍可用于回溯

内容组讲解不按单个声学片段或单段反复触发。达到 8 个稳定段落和约 1,600 字符后，后台开始判断是否换题；每次最多检查 20 段或约 4,000 字节。数量只决定何时检查，不直接决定话题边界。实时识别和翻译不会阻止内容组入队，但会在 GPU 调度中先运行；同一课程同时只保留一个内容组检查任务。打开尚未整理的历史课程时，会以幂等方式补排一项检查。页面和 ReadWeave 分别呈现内容组总结与专业名词／缩写的一句话解释，不生成疑似听写或复习问题

最终总结在录音停止且字幕、译文和材料任务排空后运行一次，因此可以使用 14B，而不占用实时翻译路径

图片 OCR、布局和视觉解释使用 Qwen3-VL 8B，普通文本模型不冒充视觉模型

## 4 云端高精度层

OpenAI 当前模型指南把 GPT-5.6 Sol 定位为复杂专业工作的旗舰模型，把 GPT-5.6 Terra 定位为智能与成本的平衡选择，两者都支持图片输入，Terra 支持 Responses API 和结构化输出

参考：[OpenAI 模型选择](https://developers.openai.com/api/docs/models)、[GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra)、[GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、[Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)

冻结用途如下：

- Terra 只处理用户逐项选择的图片或文本，用于复杂课件和本地结果复核
- Sol 只用于用户主动触发的深度复核，不进入实时自动链路
- 原始音频不发送给云端模型
- 请求必须携带项目、会话、字幕或材料页标识和本次授权
- 发送前展示范围，服务端记录授权事件和实际 Provider
- 失败时保留本地结果和可重试状态，不生成假答案

## 5 当前云端状态

可选云端 Provider 必须为 AIALRA 提供独立应用凭据，不能复用、读取或推断其他应用的密钥

当前 AIALRA Core 没有已经验收的独立云端应用凭据

因此当前生产状态保持 `cloud_enabled=false`，本轮没有绕过密钥体系、读取其他应用凭据或伪造一次云端成功

启用条件是为 AIALRA 创建单独的最小权限密钥，完成合成图片和文本的真实调用、授权审计、失败重试与请求范围读回后，再开放逐项按钮

## 6 调度规则

1. ASR 始终高于翻译、讲解、总结和图片理解
2. 翻译使用独立领取通道，滚动讲解与翻译共用常驻 7B，避免频繁切换
3. 讲解、总结和图片理解单并发
4. 图片理解只在 ASR 和翻译队列为空时开始
5. 大模型按需卸载，多个大模型不无约束常驻显存
6. OOM 或 Provider 不可用时任务重新排队，不改成 identity、deterministic 或 mock 结果

## 7 需要继续验证的边界

- 7B 段落翻译与滚动讲解尚未覆盖足够多口音、中英混说、公式口述和专业术语
- Qwen3-VL 8B 尚未建立公式、图表、扫描件和复杂版式的公开基准
- 进行中的 VLM 请求不能被稳定抢占，新录音在此时开始可能出现一次冷启动延迟
- 云端高精度层尚未取得 AIALRA 专用凭据，因此仍是关闭状态
