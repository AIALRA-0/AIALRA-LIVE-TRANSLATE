# 已知问题

状态日期：2026-08-29

## 1 长时与真实课堂证据

- 新链路已经通过 5 分钟、15 分钟和 60 分钟浏览器恢复回归，90 分钟数据完整性与恢复门禁通过，累计性能因外部 CPU 争用失败
- 真实英文课程、中英混说、多人、环境噪声、口音和生僻术语尚未形成可重复基准
- 当前不能把 30 分钟无 OOM 推导为 90 分钟稳定，也不能把单一样本延迟推导为所有课堂的 p95

## 2 采集端

- 移动浏览器锁屏和后台录音受操作系统限制，长时移动收音仍优先 Android 前台服务或 DingTalk A1 并行录制
- Android 前台收音、ACK 清理和应用内停止已有真机证据，锁屏、来电、蓝牙、Wi-Fi 切换、耗电与 90 分钟仍待验证
- 浏览器未确认块已进入 IndexedDB，但标签页被系统永久清理、浏览器数据被用户删除或磁盘不可写时仍可能丢失尚未 ACK 的音频
- 标签页或系统共享音频依赖浏览器与操作系统提供的轨道，部分受 DRM 或系统策略保护的声音不能采集
- 通知栏停止复用统一停止动作，仍需直接点击通知栏完成界面级真机复测
- Android 已能使用项目租约和 generation，但原生 Authentik 登录尚未接入，生产环境仍优先使用浏览器

## 3 实时模型

- `small + CPU int8` 的 8 秒直接基准 p95 为 2.211 秒，30 分钟端到端 p95 为 2.739 秒，已经成为当前默认值，但对其他课堂和同时运行高 CPU 程序仍需单独验证
- 14B 在 30 分钟运行中没有 OOM，但单一 LLM 通道让长讲解阻塞翻译并导致端到端延迟失败，因此没有成为默认值
- 7B CUDA 链路曾通过 30 分钟门禁，但 ASR 与 LLM 争用显存时不适合当前长时默认配置
- 当前默认 3B 模型独占 GPU，small ASR 使用 12 个 CPU 线程并提高 Worker 调度优先级，已通过独立 30 分钟门禁
- 翻译使用单段文本和有限上下文，长指代、公式口述和跨页内容可能出现语义偏差
- 周期讲解仍按稳定字幕数量触发，尚未根据停顿、困惑、页面变化或用户行为自适应
- GPU 离线时字幕为 0 并保持排队，这是预期安全行为，用户需要等待本机 Agent 恢复
- 私有网络当前往返时延会增加远程闭环总耗时，门禁需要分别记录领取、下载、推理和回传耗时

## 4 多模态材料

- 图片进入时间线并保留原图，默认解析器只提供基础元数据
- PDF、PPTX 和 DOCX 优先提取文本，复杂布局、公式、图表与扫描件需要 Docling、OCR 或视觉语言模型
- 材料相关性当前以近期页面和显式证据为主，尚未加入嵌入检索与时间锚点排序
- 摄像头与自动截屏默认关闭，尚未进入生产路径

## 5 项目与 ReadWeave

- 第一版只支持同一 Authentik 用户的多设备访问，不包含项目成员、分享邀请或多人权限
- 同一项目只允许一个录音设备，另一个项目仍可独立录音，服务器级全局录音限制不在本轮范围
- ReadWeave 只接收稳定文本和证据索引，不接收原始音频、原始课件或临时下载地址
- ReadWeave 管理标记缺失时会停止覆盖并建立恢复笔记，用户需要恢复标记或人工合并后再执行校对
- AIALRA 页面提供笔记预览，进入完整 ReadWeave 只在用户主动点击后发生，不自动打开页面

## 6 交付与运维

- 第一轮浏览器长测观察到 Core 匿名内存随 ReadWeave 全量投影高水位上升，分配器限制已经加入但仍需部署后的长测证明趋势收敛
- 项目所有权和不同用户隔离已经实现，配额、成员权限、保留期与删除策略尚未实现
- 原始音频保留期、删除、导出和备份界面尚未实现
- Windows 无任务计划程序注册权限时，Agent 使用当前用户启动项，注销后冷启动仍待验证
- 安装器现在会验证系统 Ollama 中存在 3B 模型并持久保存 Provider 配置，冷启动读回仍属于本轮剩余门禁
- 本轮验证了 Core 容器与 GPU Agent 重启，没有重启承载其他共享服务的整台服务器
- Tailscale 或等价私有网络的访问策略必须在部署环境单独配置，仓库示例不会包含真实设备、地址或令牌
- DingTalk 企业权限、A1 真机控制、录音文件列表、下载和听记对账尚未执行

## 7 公开发布边界

- 仓库不包含真实录音、逐字稿、课件、令牌、私有地址、设备标识或生产环境文件

- 旧提交、图片和二进制必须通过本地可信发布门禁，任何 `review`、`block` 或 `incomplete` 都会停止公开动作
- 2026-08-29 的公开候选已经通过工作树与完整公开历史双重门禁并完成远端读回，这次通过不自动授权未来提交，后续每次推送仍需重新执行同等门禁
