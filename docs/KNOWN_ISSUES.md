- 标签页或系统共享音频依赖浏览器与操作系统提供的轨道，部分受 DRM 或系统策略保护的声音不能采集
- 通知栏停止复用统一停止动作，仍需直接点击通知栏完成界面级真机复测
- Android 已能使用项目租约和 generation，但原生 Authentik 登录尚未接入，生产环境仍优先使用浏览器

## 3 实时模型

- 当前默认 ASR 为 `faster-whisper:small@cuda`，最新运行证明短测 p95 为 1420 毫秒，30 分钟预检 Provider p95 为 474 毫秒；90 分钟资源趋势和其他课堂仍需单独验证
- 当前翻译与滚动讲解使用 7B，运行证明短测翻译 p95 为 1624 毫秒，30 分钟预检为 1492 毫秒；更长时间的排队趋势仍需验证
- 14B 只在停止录音且实时队列排空后处理一次最终总结；最新 90 分钟轮次为 17049 毫秒并处于同步预算内，历史 90 分钟约 291 秒仍保留为失败证据
- 14B 冷启动可能超过 120 秒，页面应显示异步处理中而不是假装完成；超过异步预算时任务进入可见失败并允许手动重试
- 第一轮 3B 候选的实时链路通过，但最终总结因 Core 与 Worker 的滚动总结数量契约不一致而失败，契约已统一并加入回归测试
- 14B 总结会临时替换显存中的 7B，健康检查已允许受控模型切换，但更长课程后的恢复时间仍需在本轮长测记录
- 翻译使用连贯段落和有限上下文，长指代、公式口述和跨页内容仍可能出现语义偏差
- 周期讲解只在至少四个新段落、累计 900 字符且实时队列排空后触发，尚未根据用户困惑、页面变化或显式课堂章节自适应
- GPU 离线时字幕为 0 并保持排队，这是预期安全行为，用户需要等待本机 Agent 恢复
- 私有网络当前往返时延会增加远程闭环总耗时，门禁需要分别记录领取、下载、推理和回传耗时
- 14B 总结和图片解析现在会等待 GPU 独占窗口，长课程中若仍有实时任务排队，后台材料处理会延后，这是保护实时链路和显存稳定性的有意取舍
- 14B 总结单次处理上限为 120 秒，冷启动或显存竞争超过该时间会进入可见失败；页面可手动重试，不能生成占位总结
- 模型任务表当前仍以 `queued`、`leased`、`completed` 和 `failed` 兼容旧版本数据，`running`、`succeeded`、`retry_wait`、`cancelled` 和 `failed_visible` 仍通过事件和错误字段表达，取消接口尚未开放

## 4 多模态材料

## 5 项目与 ReadWeave

- 第一版只支持同一 Authentik 用户的多设备访问，不包含项目成员、分享邀请或多人权限
- 同一项目只允许一个录音设备，另一个项目仍可独立录音，服务器级全局录音限制不在本轮范围
- ReadWeave 只接收稳定文本和证据索引，不接收原始音频、原始课件或临时下载地址
- ReadWeave 管理标记缺失时会停止覆盖并建立恢复笔记，用户需要恢复标记或人工合并后再执行校对
- AIALRA 页面提供笔记预览，进入完整 ReadWeave 只在用户主动点击后发生，不自动打开页面
- 线上 ReadWeave ETAPI 已完成真实读写、冲突保护、幂等和离线恢复验证，90 分钟长测结果已完成，最终投影仍需在 Android 安全停止后复核
