# BabbleDeck 复用审计

## 1 结论

BabbleDeck 是重要工程参考，适合复用经验和合同，不适合直接复制业务代码

原因是两个项目的实时音频、事件、恢复和客户端壳存在明显重叠，同时当前本地仓库没有发现可确认复制权限的许可证文件

## 2 可复用经验

- WebSocket 音频分块：事件协议配置文件设定 16 字节序号和时间头，并加入 ACK 与幂等重传
- IndexedDB 恢复：浏览器纵向切片先保留未确认内存块，Android 已实现持久缓存，浏览器持久缓存待补
- SSE 实时查看：先回放 SQLite 历史，再订阅实时广播
- 事件模型：使用版本化追加事件和修订，旧结果保留在事件流中
- Soniox Provider：只作为未来可选云端适配，不进入默认本地路径
- Tauri 和 Capacitor：保留壳层经验，Android 主录音改用 Kotlin 原生前台服务
- 生产运维：延续结构化日志、健康检查、恢复和导出门禁思路

## 3 明确不复制的内容

- 未确认许可证的业务源文件
- BabbleDeck 的普通会议产品定位及数据库模型
- 默认依赖 Soniox 或 LiveKit 的云端链路
- 与课程证据、A1 设备和本地模型调度无关的功能

## 4 复审条件

如果 BabbleDeck 后续加入明确许可证、稳定协议包或可共享组件，项目可以重新审查依赖方式

任何复用都需要保留来源、版本、许可证和差异记录
