# ADR 0010：ReadWeave 作为可重建笔记投影

状态：已接受

日期：2026-08-28

## 1 背景

课程字幕、译文、解释和材料索引需要进入用户可持续整理的笔记目录，同时不能让外部笔记状态取代 AIALRA 的追加式事件事实源

ReadWeave 基于 TriliumNext ETAPI，支持外部自动化、修订和层级笔记，适合作为课程笔记投影目标

## 2 决策

- AIALRA 事件库保持事实源，ReadWeave 内容可以从项目和会话事件重新生成
- Core 通过私有网络访问 ETAPI；令牌只保存在部署 Secret 中，不进入浏览器、数据库内容或普通日志
- 每个项目和会话使用稳定远端对象映射，连接器任务使用 SQLite 持久队列、租约、退避和幂等键
- 稳定字幕与译文按 30 秒批次投影，停止录音后执行最终校对
- 每次更新先创建 ETAPI revision，再读取远端内容并只替换 AIALRA 管理标记之间的区域
- 管理标记外的人工内容保持不变；标记缺失或结构冲突时停止覆盖并创建恢复副本
- `99 我的笔记` 只由用户编辑，AIALRA 不自动写入其正文
- 默认只投影稳定文本、解释和材料证据索引，不上传原始音频、原始课件或临时下载地址

## 3 结果

- ReadWeave 离线不会阻塞录音、字幕或停止；连接器任务在服务恢复后继续执行
- 用户可以在 AIALRA 同一页面预览同步状态和笔记内容，只有主动操作才会在当前标签进入 ReadWeave
- 远端人工编辑与自动内容拥有明确边界，冲突会转为可见状态而不是静默覆盖
- 删除远端投影不会删除 AIALRA 事件，但重新生成前仍需要保留有效 ETAPI 配置和项目映射策略
