# ADR 0009：项目所有权与单录音租约

状态：已接受

日期：2026-08-28

## 1 背景

同一用户需要在电脑、手机和观察设备上看到相同课程项目，但同一项目同时只能有一个设备上传录音

旧会话没有项目和用户归属，旧音频接口也无法证明上传设备持有当前录音权

## 2 决策

- 生产环境普通请求以受信任反向代理写入的 `X-authentik-uid` 作为所有者主键；音频 WebSocket 允许使用已签发且绑定项目与会话的租约子协议恢复所有者身份，因为浏览器不能为 WebSocket 设置 `Authorization` 头，Core 仍会独立校验租约有效期和会话范围
- 本地开发固定使用 `local-user`，不模拟生产身份头
- 会话必须归入项目；第一版只允许同一所有者在多设备之间同步，不开放成员共享
- 同一项目同时只允许一个有效录音租约；客户端每 10 秒续期，租约 45 秒后失效
- 租约密钥只返回一次，数据库只保存 SHA-256 摘要；WebSocket 通过子协议头传递密钥，不把密钥放入 URL
- 接管录音时递增 `generation`，音频来源 ID 包含该代次；旧租约和旧来源不能继续写入
- 项目更新使用持久递增游标，SSE 按 `Last-Event-ID` 补齐断线期间的项目、会话和租约变化
- 历史会话只在服务启动时分配给明确配置的所有者，访问项目列表不会自动认领旧数据

## 3 结果

- 多设备可以读取同一项目和追加式时间线，第二个录音设备会得到 `409 recording_lease_conflict`
- 原设备在 45 秒内可以使用原租约恢复；租约过期后其他设备可以接管
- 音频接收仍先落盘再 ACK，身份和租约检查不会把模型任务放进接收请求路径
- 原生客户端的普通生产 API 仍需要完成与 Authentik 兼容的登录流程；Android 音频 WebSocket 使用配对后得到的设备 Bearer 凭证，浏览器音频 WebSocket 使用项目录音租约
