## 3 本轮暴露并修复的问题

### 3.1 重复音频被错误去重

第一轮 90 分钟测试在早期观察到 2020 个音频块、404 个持久窗口，却只有 4 个 ASR 完成

原因是 ASR 幂等键只使用音频内容哈希，可重复测试音频在再次出现时被当成同一个任务

修复后，幂等键同时包含会话、来源、采集时间和内容哈希，相同音频在不同时间产生不同任务，同一时间点的真实重传仍保持幂等

该轮结果无效并保留为失败证据，没有计入长测通过

### 3.2 单一 LLM 通道阻塞翻译

修复 ASR 幂等键后的第一轮 30 分钟运行收到 1783／1783 个 ACK，产生 357 条字幕、357 条译文和 70 张讲解卡，重复字幕与 OOM 都为 0

应用层推理耗时通过，但数据库报告发现：

| 指标 | 结果 | 门禁 |
|---|---:|---:|
| Worker 领取 p95 | 10.553 秒 | 2 秒 |
| ASR 端到端 p95 | 2.996 秒 | 3 秒 |
| 翻译端到端 p95 | 14.323 秒 | 8 秒 |
| 讲解端到端 p95 | 32.671 秒 | 20 秒 |

原因是翻译和长讲解共享同一领取通道，讲解执行期间新翻译只能排队

该轮没有计入通过

### 3.3 7B 单并发仍会持续排队

把 ASR、翻译和讲解拆成独立领取通道并切换到 7B 后，5 分钟预检通过

后续 30 分钟重跑在约 17 分钟时发现 Ollama 仍按单并发处理真实长讲解，翻译端到端 p95 上升到 13.698 秒

该轮被提前停止并正常释放录音租约，没有用剩余时间掩盖失败趋势

最终修订把 Ollama 设为双并发，并保留独立 ASR、翻译和讲解通道

## 5 项目、多设备与租约

自动验证范围：

- 不同 Authentik UID 不能读取彼此项目
- 项目列表不能隐式认领历史会话
- 同一用户的两个设备得到相同项目和时间线
- 同一项目只有一个设备取得有效录音租约
- 第二个设备得到明确的 `409 recording_lease_conflict`
- 45 秒内原设备可恢复，过期后新设备接管并递增 generation
- 长于 45 秒的断网若没有设备接管，原设备仍可原地续回并补传缓存
- 旧租约和旧 generation 不能继续上传
- 录音租约的服务端令牌摘要不会出现在续期响应、项目更新或普通日志
- SSE 使用 `Last-Event-ID` 补齐更新且不重复
- 停止后观察设备同步得到录音停止和模型处理状态

## 6 音频恢复

自动验证范围：

- ACK 只在音频对象和 SQLite 同时提交后返回
- 重复发送相同帧只保留一个提交结果
- 同序号但不同内容的重传被拒绝
- 第 2 帧先到时装配器等待第 1 帧
- 第 1 帧补到后形成一个连续窗口
- Core 在未满窗口和完整窗口入队后重启均能继续装配
- 停止时从持久块封存尾部
- 浏览器刷新时恢复 IndexedDB 未确认帧
- 所有 ACK 完成后再次刷新不会重新使用序号 1
