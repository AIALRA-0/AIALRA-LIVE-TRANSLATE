# AIALRA-LIVE-TRANSLATE 验证报告

状态日期：2026-08-27

## 1 结论

本轮已经证明以下结构可以真实工作：浏览器或测试客户端发送音频，服务器先持久化并 ACK，SQLite 队列在 GPU 离线时保留模型任务，本机 RTX 4080 恢复后生成真实 CUDA 字幕、译文和讲解

本轮没有证明 30 分钟或 90 分钟长时稳定、所有课堂口音与噪声质量、DingTalk A1 连续第三方音频能力，也没有把这些项目计入通过

## 3 本机真实 GPU 闭环

测试条件：

- 输入：公开合成英语课程音频，不含用户录音或真实课程材料
- GPU：RTX 4080 16 GB
- ASR：`faster-whisper:small@cuda`
- 翻译与讲解：`ollama:qwen2.5:14b-instruct@cuda`
- 音频块：21 个

结果：

|---|---:|
| 音频 ACK | 21／21 |
| 稳定字幕 | 4 |
| 稳定译文 | 4 |
| 材料页 | 1 |
| 讲解卡 | 1 |
| 完整闭环 | 14.201 秒 |

## 5 离线、恢复与重启

### 5.1 GPU 离线

1. 停止 GPU Agent 并等待 Worker 状态转为离线
2. 发送 21 个音频块
3. 全部音频块获得服务器 ACK
4. 最终字幕为 0，数据库保留 5 个模型任务

这证明 GPU 离线不会阻塞接收、持久化、确认和停止，也不会生成假字幕

### 5.2 GPU 恢复

1. 重新启动 Agent
2. 未完成任务自动领取
3. 产生 4 条字幕与 4 条译文
4. 重复字幕为 0

### 5.3 Core 重启

1. 在 5 个任务排队且会话处于 `processing` 时重启 Core
2. 重启后 5 个任务仍存在，会话仍为 `processing`
3. Agent 恢复后产生 4 条字幕与 4 条译文
4. 重复字幕为 0

本轮未重启承载其他共享服务的整台服务器，不能把 Core 重启结果表述为整机断电恢复

## 6 浏览器与视觉验证

真实 Chromium 验证范围：

- 页面只保留单一课程工作台，不自动打开新页面
- 生产没有默认演示开关和 `/demo` 路由
- GPU 离线时显示音频安全保存与排队，不显示占位字幕
- 麦克风通过 AudioWorklet 采集，未确认块写入 IndexedDB
- 标签页或系统共享音频通过 `getDisplayMedia` 进入相同上传路径，并保留来源 ID
- 停止后不再采集新音频，页面区分录音停止与模型处理完成
- 桌面、暗色与 390 px 窄屏均无绿色残留和页面级横向溢出
- 浏览器控制台错误与警告为 0

README 图片来自本轮真实 GPU 合成样本页面，标识符已缩略，图片经过重新编码并移除元数据

## 7 安全与线上边界

- 公网匿名访问返回登录跳转
- 伪造身份头不能绕过登录
- 公网 `/internal/` 固定拒绝
- Worker Gateway 只在私有网络接口监听
- VPS 只保存 Worker 令牌摘要，Windows 令牌使用 DPAPI 保存
- 普通 Agent 日志只记录任务 ID、状态、耗时和错误分类
- VPS CPU Worker 与默认 Ollama 服务已从当前主路径停用
- 环境文件、真实域名、地址、设备、令牌和用户内容不进入仓库
